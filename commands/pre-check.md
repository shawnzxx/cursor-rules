# Pre-Check & Auto-Fix Workflow

触发命令: `/pre-check`

你现在的任务是确保修改完代码后通过运行lint检查和测试,做check in代码前的最后验收,请严格按照以下顺序执行：

## 第一阶段：Linter 检查与修复

### 步骤 1.1：运行 Linter

首先执行 `make go-lint` 命令。

### 步骤 1.2：处理 Linter 错误

- **如果有报错**：
    1. 分析报错信息，准确定位代码中的格式/语法问题。
    2. **自动修复**：直接修改相关源文件以解决问题。
    3. **再次验证**：修复后，**必须自动回到步骤 1.1** 重新运行 `make go-lint`。
    4. 重复此过程直到 `make go-lint` 通过（Exit Code 0）。

- **如果 `make go-lint` 成功 (Exit Code 0)**：
    1. 进入第二阶段。

## 第二阶段：测试检查与修复

### 步骤 2.1：运行测试

在 linter 通过后，执行 `make test` 命令。

### 步骤 2.2：处理测试错误

- **如果有报错**：
    1. 分析报错信息，准确定位代码中的 Bug 或逻辑问题。
    2. **自动修复**：直接修改相关源文件以解决问题。
    3. **再次验证**：修复后，**必须自动回到步骤 2.1** 重新运行 `make test`。
    4. 重复此过程直到 `make test` 通过（Exit Code 0）。

- **如果 `make test` 成功 (Exit Code 0)**：
    1. 停止操作。
    2. 简要总结修复了哪些问题（如果没有修改，则说明项目状态良好）。
    3. 报告："✅ 所有检查已通过"。

## 3. 注意事项

- **严格顺序**：必须先完成 linter 检查并通过，才能进行测试检查。
- **循环限制**：如果同一个错误循环 3 次仍未修复，请停止并向我说明原因，不要陷入死循环。
- **代码理解**：在修改代码前，请确保你已经读取了相关的上下文文件。
